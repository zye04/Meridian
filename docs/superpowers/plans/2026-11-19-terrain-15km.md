# 15 km Terrain (M1) Implementation Plan

**Status:** done on main (M1, 4a6cc04..aa5dbe3).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 2 km procedural terrain mesh with a 15 km real-elevation heightfield (Napf, swissALTI3D 2 m) rendered with GPU-selected CDLOD, heightfield-marched sun shadows, camera-relative precision, a curvature display warp out to the horizon, and walk mode.

**Architecture:** The heightfield (uint16 + scale/offset) and a min/max pyramid live in GPU buffers reached through `GpuTerrain` in the scene buffer. A compute pass selects quadtree nodes per level each frame; a terrain mesh shader draws them (8x8-quad workgroups, geomorphing) first in the early scene pass; a `TERRAIN` variant of `mesh.frag` shades them. Shadow rays add a hierarchical heightfield march to the existing TLAS query. All raster shaders work camera-relative and apply the curvature drop; lighting runs in the flat world.

**Tech Stack:** C++20, Vulkan 1.3, `VK_EXT_mesh_shader`, ray queries, GLSL (glslc), doctest, bash + curl + jq + ImageMagick for data.

**Spec:** `docs/superpowers/specs/2026-11-19-terrain-15km-design.md` (read it with this plan).

## Global Constraints

- Conventions (CLAUDE.md): meters; y = elevation above sea level; right-handed, Y up, camera looks down -Z; reverse-Z, infinite far; `Mat4` column-major `m[column][row]`; motion vectors = previous - current in UV.
- World mapping: crop center = origin; east = +x; north = -z. Heightfield sample (i, j) sits at x = (i - (width-1)/2) * spacing, z = (j - (height-1)/2) * spacing; row j = 0 is the north edge.
- Outside the samples, indices mirror like Vulkan `MIRRORED_REPEAT` (edge sample duplicated, period 2*width): `mirror(i) = m < w ? m : 2w-1-m` with `m = i mod 2w` (non-negative modulo). CPU and GPU use this same rule.
- Napf crop: swissALTI3D 2 m tiles E 2631..2645, N 1198..1212 (LV95 km, 15 x 15 tiles, 7500 x 7500 samples, spacing 2 m). Attribution "© swisstopo".
- Budgets (2560x1440, Release, RTX 4080, median of 5): CDLOD selection + terrain raster <= 0.3 ms over the current terrain material cost; shadow march <= 0.6 ms over all pixels at the open view. A miss: stop, report numbers to the user; levers: march quality/length, then LOD density, never the material.
- No new third-party dependencies. Every struct marked "must match" changes together with its GLSL twin (static_assert sizes).
- Each task is one commit (one feature) with a message explaining what and why, **no AI attribution / Co-Authored-By trailer**, pushed to `main`. CLAUDE.md and `docs/decisions.md` are updated in the same commit as the change they describe (decisions with sources).
- Every task: `cmake --build build` (Debug: ASan+UBSan+validation) succeeds; `ctest --test-dir build` passes; capture runs report 0 validation errors.
- Release perf runs use a separate build in the session scratchpad: `cmake -S . -B $SCRATCH/release -DCMAKE_BUILD_TYPE=Release && cmake --build $SCRATCH/release`.

## Review Focus

1. Camera crossing CDLOD range/morph boundaries while moving: no cracks, no popping, motion vectors without smear (Task 4 motion capture through a morph zone).
2. Camera outside the crop and rays crossing the crop edge: CPU `heightAt`, raster terrain and the shadow march agree across the mirror seam (Task 3 unit test on mirrored samples; Task 5 brute-force A/B capture of a view across the edge).
3. High camera (overview, ~5 km altitude) and wide views: terrain node list never overflows silently; overflow is counted in `droppedCullEntryCount` (Task 4 capture at the high overview prints 0 dropped).
4. Grazing sun (sunset, sun 2-5 degrees up): march terminates within its step bound, no terrain self-shadow acne on lit slopes, no light leaks through ridges (Task 5 sunset capture vs brute-force).
5. Missing or partial elevation data: the fetch script fails loudly on any missing tile; the game falls back to the procedural heightfield and prints how to fetch (Task 3 script check; Task 4 run with the file renamed).

- Produces (in `terrain.h`, namespace `meridian`):

```cpp
struct Heightfield {
  uint32_t width = 0;   // samples per row (east-west)
  uint32_t height = 0;  // rows (north to south)
  float spacing = 2.0f; // meters between samples
  float minHeight = 0.0f;
  float heightScale = 1.0f; // meters per sample step
  std::vector<uint16_t> samples; // row-major, row 0 = north edge

  // Height of sample (i, j), any integers: indices mirror outside the grid.
  float sample(int64_t i, int64_t j) const;
  // Bilinear height at world (x, z), same mirroring (matches the GPU).
  float heightAt(float x, float z) const;
};

struct HeightfieldSettings { // procedural fallback
  uint32_t resolution = 2048;
  float spacing = 4.0f;
  float baseHeight = 500.0f;
  float maxHeight = 600.0f; // relief above baseHeight
  uint32_t seed = 1;
};

Heightfield generateHeightfield(const HeightfieldSettings &settings); // existing value noise
Heightfield loadHeightfield(const std::filesystem::path &path);       // throws on bad file
void saveHeightfield(const Heightfield &field, const std::filesystem::path &path);
Heightfield quantizeHeightfield(std::span<const float> heights, uint32_t width,
                                uint32_t height, float spacing); // min/scale from data

// Min/max pyramid for culling bounds and the shadow march. Level 0 is the
// samples; level k+1 texel (x, z) covers level-k texels 2x..2x+1, 2z..2z+1
// (clamped to the level). Level sizes are ceil(previous / 2), down to 1x1.
struct HeightPyramidLevel { uint32_t width, height; std::vector<uint32_t> minMax; }; // min | max << 16
std::vector<HeightPyramidLevel> buildHeightPyramid(const Heightfield &field);
```

- `.height` file: little-endian header `{char magic[4] = "MHF1"; uint32 version = 1; uint32 width, height; float spacing, minHeight, heightScale;}` then `width*height` uint16.

**Interfaces:**
- Produces in `terrain.glsl`: `bool terrainOccludes(vec3 worldOrigin, vec3 direction, float maxDistance)` — hierarchical max-pyramid march in the flat world: at each step use the coarsest level whose max over the current cell is below the ray, advance to the cell exit, descend on overlap, test bilinear height at level 0; mirrored coordinates outside the crop (steps never cross a mirror seam inside one coarse cell: clip step length at the crop boundary). Hard step cap 256; reaching it counts as unoccluded. Brute-force variant: fixed 1 m steps for 2 km, then 8 m steps to `maxDistance`, bilinear height.
