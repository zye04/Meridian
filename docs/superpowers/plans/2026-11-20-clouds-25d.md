## Task 1 — renderer switch and the slab pass skeleton

Status: todo

- `renderer.h`: `enum class CloudRenderer { Off, Volumetric, Slab };`
  `Renderer::setCloudRenderer(CloudRenderer)` replaces
  `setCloudsEnabled` (`renderer_impl.h` `cloudRenderer`, default
  Volumetric). Every `cloudsEnabled` use becomes `!= Off`; the march /
  resolve / composite dispatches only for Volumetric.
- `GpuClouds::pad1` -> `uint32_t renderer` (0 off, 1 volumetric, 2
  slab), mirrored in `common.glsl` `Clouds` (`uint renderer`), filled from
  the impl each frame.
- `game/src/main.cpp`: `--clouds 2.5d|volumetric|off` (`on` = the
  default); usage text.
- Move `haze()` from `clouds_march.comp` into `clouds_march.glsl`
  unchanged (shared with the new pass).
- New `engine/shaders/clouds_slab.comp` (`add_shader`), pipeline on
  `cloudMarchLayout` with the resolution-0 set (it uses bindings 0 depth,
  7 HDR, 8 motion, 10 mask), dispatched at `renderExtent` in a
  `drawCloudsSlab` in `renderer_clouds.cpp`, same layout transitions as
  `drawClouds`; endPass("clouds") unchanged so the GPU table row stays.
  Skeleton body: composite nothing (writes nothing).
- Verify: both builds; `--clouds volumetric` capture identical to main
  (mean diff ~0); `--clouds 2.5d` capture = clear sky, no validation
  errors; `--clouds off` as before.

## Task 2 — the slab field and the view pass

Status: todo

- `engine/shaders/clouds_slab.glsl` (new): `SlabColumn slabColumn(vec2
  xz)` -> base, thickness, type, coverage (spec formulas: `weatherMapAt`,
  noise slices of `baseNoise` / `detailNoise` at a time-advancing slice,
  wind offset, `cut`, `dome`, rim lift); `float slabDensity(vec3 world)`
  (soft edges); `CloudMarch marchSlab(direction, tStart, tEnd, steps,
  ambient)`: deterministic steps, trapezoid integration, lighting on
  cloudy steps (sun taps along the column + `cloudShadow` beyond, the
  `clouds_march.glsl` phase / octaves / diffuse / ambient constants,
  normal from the thickness gradient), mean depth like `marchClouds`.
- `clouds_slab.comp`: jittered ray from `viewProjection` per pixel,
  span (`cloudLayerSpan` envelope), scene-depth cut, `marchSlab`,
  `withCirrus` on sky pixels, `haze`, premultiplied composite over HDR,
  motion via `cloudPreviousClip` (include `clouds_temporal.glsl`) where
  opacity > 0.5, mask raised to opacity.
- Verify: the cloud views (fair from 1500 m, cumulus from the ground,
  broken, overcast, sunset from above, dusk, summit silhouette) captured
  for 2.5d and volumetric side by side; 0 validation errors (Debug run);
  `clouds` GPU ms recorded.
- Opus review of clouds_slab.glsl / clouds_slab.comp after this task.

## Task 3 — far weather cascade

Status: todo

- Second weather map image (same format), 1024^2 over 480 km, placed and
  snapped like `placeWeatherMap` (`GpuClouds` gains its origin and
  size, `common.glsl` too, static_asserts), written by
  `weather_map.comp` with a push-constant cascade index and a row phase
  (one of 4 rows per frame; all rows on the first frame).
  `weatherMapAt`: near map, else far map inside its texel centres, else
  the analytic fallback; the far map's edge blends to the fallback like
  the near map's. Applies to both renderers (a cost win for volumetric
  too; image change only beyond 30 km, checked with a capture A/B).
- CPU placement math in a testable function; a unit test (snapping,
  containment of the camera).
- Verify: tests; captures before/after (far clouds unchanged in
  character); `weather` and `clouds` ms.
