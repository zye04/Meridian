# M2a Forests Implementation Plan

**Status:** Tasks 1-7 done on main; Tasks 8-12 not started.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Millions of deterministic, rule-placed Megascans trees and rocks on the Napf, culled by cell, drawn through a cluster-group BVH traversal near, hemi-octahedral impostors mid-range and a per-cell voxel-brick far field beyond ~4 km, all casting RT sun shadows (TLAS built once; far receivers march the voxels).

**Architecture:** Placement runs once at load in compute (integer rules, three-step count/scan/write) into a resident 24-byte placed-instance table sorted by 64 m cell. Per frame, a cell cull feeds the instance cull, which picks impostor or clusters and seeds a breadth-first BVH traversal over each mesh's per-level cluster groups; leaves feed the existing cluster cull and draw lists. One static TLAS over one multi-geometry BLAS per prototype is filled by compute and built when the instance set changes. Far cells skip their tree instances and are drawn as one voxel-brick aggregate each, splatted at load from the placed table; the same bricks are the far ray field (spec `docs/superpowers/specs/2026-11-20-far-field-design.md`, decided 2026-11-20).

**Tech Stack:** C++20, Vulkan 1.3, `VK_EXT_mesh_shader`, ray queries, GLSL, doctest, meshoptimizer 1.0 (pinned), Python 3 + `usd-core` (offline import only).

**Spec:** `docs/superpowers/specs/2026-11-19-forests-design.md` (read it with this plan). Starts after M1 (`docs/superpowers/plans/2026-11-19-terrain-15km.md`) is complete on main: it assumes `terrainOccludes`, `curvatureDrop`, GPU `terrain.glsl` sampling and walk mode exist.

## Global Constraints

- Conventions (CLAUDE.md): meters, Y up, right-handed, camera down -Z; reverse-Z infinite far; camera-relative positions in every shader; motion vectors previous - current in UV; `curvatureDrop` applied to every raster stage and every culling bound (impostors and cells included).
- Placement keep/reject is bit-exact on any GPU, driver and the CPU: integer or fixed-point hashes, noise and rule math only on that path (no transcendentals, no float `smoothstep`); rule altitude/slope from the 16-bit samples in integer math; instance height `heightAt`-exact. Placement stays inside the heightfield crop.
- Placed instance: 24 bytes (3 x f32 world position, quaternion xyz snorm16 with w >= 0, f16 uniform scale, u32 prototype). Cells 64 m. No wind bytes. Instance ids share one 24-bit space (TLAS custom index); ids >= `placedBase` index the placed table.
- One BLAS per prototype (each mesh a geometry, full detail, compacted), one TLAS record per placed object; hand-placed instances keep a BLAS per mesh.
- VRAM: everything M2a adds leaves >= 3 GB of 16 GB free at the forest views.
- Every queue/list has a fixed capacity; overflow dropped, counted, printed by capture runs (must be 0 in every verification capture).
- Load-time results that exceed ~5 s (impostor bake, transition measurement, far-field prototype bake) are cached on disk next to the cooked tree, versioned and validated like `.clusters`.
- Done bar: forest views (edge, interior, overview) <= 16.7 ms per frame with RT shadows on; trees and rocks (all culls + cluster, impostor and far-field raster) <= 2.0 ms at the forest-edge view. Release, 2560x1440, median of 5.
- GPU lock (user, 2026-11-19): every run of the game binary in either lane, captures and perf runs, Debug or Release, goes through one lock so GPU work never overlaps: `flock /tmp/meridian-gpu.lock ./build/game/game ...`. Hold it only for the run, never for builds.
- New tooling dependency allowed only as specified: `usd-core` pinned in `tools/usd2gltf/requirements.txt`, git-ignored venv. No new engine dependencies.
- Each task is one commit with a what-and-why message, **no AI attribution / Co-Authored-By trailer**, CLAUDE.md and `docs/decisions.md` (with sources) updated in the same commit; every "must match" struct changes with its GLSL twin.
- Every task: `cmake --build build` (Debug: ASan+UBSan+validation) succeeds, `ctest --test-dir build` passes, captures report 0 validation errors. Release perf builds in the session scratchpad.

## Review Focus

1. Camera far outside the crop or high above it (overview, `6500 3500 0` edge view): cells, far cells, impostors and the traversal never overflow silently and nothing is placed in mirrored terrain (Task 5 capture prints 0 dropped; Task 3 test: no instance outside the crop).
2. A prototype whose DAG has a single level or a mesh with fewer than 128 triangles (rocks, saplings): BVH build and traversal still select exactly the flat cut (Task 6 test on a 1-cluster mesh).
3. Camera exactly at an impostor transition size, moving back and forth: no flicker, no double-drawn or missing tree (Task 11 motion captures oscillating across the impostor transition and the far switch).
4. Placement with a layer that keeps zero points (rule thresholds that reject everything) or a cell at the crop corner: count/scan/write handles empty ranges; determinism holds (Task 3 test with an all-reject layer; Task 4 Debug equality check).
5. Re-running the game after an asset or bake-setting change: stale `.clusters` (BVH version) and impostor caches are rebuilt, never misread (Task 6 and Task 10 cache tests with a changed key).
